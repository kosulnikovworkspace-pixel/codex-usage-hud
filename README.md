# Codex Usage HUD

Небольшое локальное расширение для Comet и других Chromium браузеров. Оно показывает поверх `chatgpt.com` использование 5-часового и недельного лимитов Codex, время до их сброса и время последнего обновления. HUD можно свернуть; его состояние и последний успешный результат сохраняются локально.

API key, отдельный backend, аккаунт расширения и сборка не нужны. Расширение не отправляет данные разработчику или стороннему серверу. Запросы идут только на `https://chatgpt.com` через уже открытую веб-сессию. Временный access token читается из `/api/auth/session` только в памяти для заголовков запросов; он не сохраняется и не выводится в журнал.

## Установка

1. Откройте в Comet страницу управления расширениями через меню браузера.
2. Включите **Developer mode**.
3. Нажмите **Load unpacked**.
4. Выберите корневую папку `codex-usage-hud`, в которой лежит `manifest.json`.
5. Откройте или перезагрузите `https://chatgpt.com` после входа в свой аккаунт.

В другом Chromium браузере шаги те же. При изменении файлов нажмите **Reload** на странице расширений и перезагрузите вкладку ChatGPT. Чтобы удалить расширение, нажмите **Remove** на этой же странице.

## Откуда берутся данные

`src/usage-client.js` сначала получает текущую сессию через `/api/auth/session`, затем запрашивает `/backend-api/wham/usage` с временным Bearer token. Окна лимитов определяются по `limit_window_seconds`, а не по порядку. При отсутствии поля HUD показывает `—`; при ошибке сохраняет прежние данные и показывает короткий статус. В консоль выводятся только этап, HTTP status, код и время ошибки.

Эти endpoints **не являются публичным стабильным API**. Их схему и требования к авторизации необходимо подтвердить в действующей сессии Comet. В окружении разработки не было доступа к авторизованной сессии ChatGPT, поэтому реальный ответ пока не проверен. Если правила авторизации или структура ответа изменятся, данные могут не загрузиться.

## Если данные не загружаются

Проверьте, что вы вошли на `chatgpt.com`, затем нажмите **Refresh** (круговая стрелка). Если отображается `Usage data unavailable`, подробная безопасная запись с этапом, HTTP status или кодом ошибки и временем находится в консоли вкладки. Если проблема сохраняется, внутренний endpoint мог изменить формат или правила доступа. Для исправления обычно достаточно обновить `src/usage-client.js`. Не публикуйте ответы API, cookies или заголовки авторизации при диагностике.

## Файлы и проверки

- `manifest.json` — Manifest V3; единственное permission — `storage`, доступ content script ограничен `https://chatgpt.com/*`.
- `src/usage-client.js` — запросы и нормализация ответов.
- `src/format.js` — форматирование значений.
- `src/content.js`, `src/hud.css` — HUD, обновление, сохранение состояния и темы.
- `test/usage.test.js` — тесты без сторонних зависимостей.

Проверки: `node --test test/*.test.js`, `node --check` для каждого JS-файла, а также JSON-проверка `manifest.json`. Папку проекта можно напрямую передать в **Load unpacked**.
